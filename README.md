# Handmade — сайт мастерской на PHP + MySQL

> **Laravel-версия:** бэкенд пересобран на Laravel 12 в папке [`laravel/`](laravel/README.md). Запуск: `laravel\setup.cmd`, затем `laravel\start.cmd` → <http://127.0.0.1:8002>. Ниже описана исходная версия на чистом PHP.

Фронт магазина (украшения из бисера и вязаные игрушки) подключён к бэкенду: каталог, заказы, заявки, контакты и доставка хранятся в MySQL и редактируются в админке. Node.js и сборка не нужны — обычный виртуальный хостинг с PHP.

## Быстрый старт

Нужны **PHP 8.1+** (с `pdo_mysql`) и запущенный **MySQL 5.7+ / MariaDB 10.3+**.

1. Скопируйте `backend/.env.example` в `backend/.env` (файл `.env` уже есть — проверьте значения).
2. Укажите доступы к базе и секрет:
   ```
   DB_HOST=localhost
   DB_PORT=3306
   DB_NAME=handmade
   DB_USER=root
   DB_PASS=
   JWT_SECRET=длинная-случайная-строка-не-короче-32-символов
   ```
3. Запустите `setup.cmd` (или `php backend/bin/install.php`). Скрипт создаст базу, таблицы, каталог и первого админа.
4. Запустите `start.cmd` — сайт откроется на <http://localhost:4000>, админка на <http://localhost:4000/admin>.
   Логин по умолчанию: `admin@handmade.ru` / `handmade2026` (меняется в `backend/.env` до установки и в админке после).

Если MySQL уже настроен в OSPanel, можно направить домен прямо на эту папку — структура рассчитана и на Apache, и на встроенный сервер PHP.

## Что где лежит

```
index.html, catalog.html, product.html, checkout.html   страницы сайта
products.js        локальный резерв каталога + загрузка из /api/shop/catalog
script.js          корзина, поиск, товар, оформление заказа, заявки
api-client.js      мини-клиент API для обычных страниц
config.js          адрес API (по умолчанию /api)
style.css          стили сайта
css/style.css      базовые стили админки
admin/             админка (/admin)
api/index.php      точка входа API: все запросы /api/*
backend/           код API, вне публичного доступа (закрыт .htaccess и router.php)
  .env             настройки
  app.php          реестр модулей, пресет shop
  modules/         settings, auth, pages, leads, media, shop
  sql/             schema.sql, seed.sql
  bin/install.php  установка базы
uploads/           картинки, загруженные из админки
```

## Что связано с бэкендом

- **Каталог** — `/api/shop/catalog`. Товары и категории приходят из MySQL; если API недоступен, сайт показывает встроенный резервный набор из `products.js`, поэтому вёрстку можно открывать и без PHP.
- **Карточка товара** — цена, описание, характеристики и фото берутся из базы. Ссылка остаётся `product.html?id=<slug>`.
- **Корзина** — по-прежнему в `localStorage` (гостю не нужен вход). При оформлении на сервер уходят только `slug` и количество.
- **Заказ** — `POST /api/shop/orders`. Сервер сам проверяет товары, пересчитывает цены, доставку и итог, создаёт номер вида `HM-8F3K2`, сохраняет заказ и позиции, отправляет уведомление админу. Клиентские суммы не принимаются.
- **Доставка** — стоимость, порог бесплатной доставки, срок и адрес самовывоза хранятся в настройке `shop` и редактируются в админке: «Сайт → Доставка».
- **Индивидуальный заказ** — кнопки «Индивидуальные заказы» и «Обсудить заказ» открывают форму; заявка уходит в `POST /api/leads` и видна в админке в разделе «Заявки».
- **Контакты и соцсети** — `GET /api/site`; телефон, e-mail, адрес, часы работы и ссылки в подвале обновляются из админки.
- **Админка** — заказы, товары, заявки, контакты, доставка. В простом режиме (`config.js → admin.mode: 'simple'`) заказчик видит только рабочие разделы; полный режим включается ссылкой `/admin?full=1`.

## API

Публичные:

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/health` | проверка БД и модулей |
| GET | `/api/site` | карточка сайта и контакты |
| GET | `/api/shop/catalog?cat=&q=` | категории, товары, настройки доставки |
| GET | `/api/shop/products/:slug` | один товар |
| GET | `/api/shop/config` | доставка |
| POST | `/api/shop/orders` | оформить заказ |
| POST | `/api/leads` | заявка с формы |

Админские (`Authorization: Bearer <token>`): `/api/admin/auth/*`, `/api/admin/shop/categories`, `/api/admin/shop/products`, `/api/admin/shop/orders`, `/api/admin/shop/settings`, `/api/admin/leads`, `/api/admin/media`, `/api/admin/settings/site`.

## Выкладка на хостинг

1. Загрузите содержимое папки в `public_html`.
2. Чтобы код бэкенда не лежал в публичной папке, можно перенести `backend/` выше `public_html` и поправить путь в `api/index.php` (он уже ищет `../backend/app.php`). В этой сборке `backend/` закрыт правилами Apache.
3. Создайте `backend/.env` с боевыми доступами, `APP_ENV=production`, новым `JWT_SECRET`.
4. Импортируйте `backend/sql/schema.sql` и данные установщиком `php backend/bin/install.php` либо через phpMyAdmin.
5. Включите SMTP, чтобы клиенты получали письмо о заказе, и `MAIL_ADMIN_TO` — чтобы заказы и заявки приходили на почту. Telegram-уведомления включаются `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
6. Для nginx направьте `/api/` на `api/index.php`, остальное отдавайте статикой (см. пример в README исходного шаблона бэкенда).

## Деньги и данные

- Все суммы в базе и API — **в копейках** (`690 ₽` = `69000`).
- Время в MySQL — UTC, часовой пояс сайта задаётся `TIMEZONE` в `.env`.
- Товар нельзя удалить физически «вместе с историей»: позиции заказа хранят копию названия и цены. При удалении товара ссылка в позициях обнуляется, заказ остаётся.
- Повторная установка не дублирует данные. `php backend/bin/install.php --replace-shop` заменяет каталог данными из `seed.sql`.
